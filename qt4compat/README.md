# qt4compat: Kate on plain Qt 4 without kdelibs

This directory is a compatibility layer that lets the KDE 4.14 Kate/KatePart
sources build against Qt 4.8 only. It provides the kdelibs classes Kate uses,
either as thin wrappers over Qt or as vendored kdelibs 4.14 sources (LGPL 2.1)
with their KDE-specific dependencies cut. There is no D-Bus, no kdeinit,
no ksycoca, no KIO: everything is local files and in-process (`KIO::NetAccess`
offers synchronous local-file helpers; `kjob.h` only forward-declares `KJob`,
there are no jobs).

Target: macOS 10.5/10.6 PowerPC, Qt 4.8.7, built as `-std=gnu++98` with the
same compiler as Qt 4 (Apple gcc on 10.6; a mismatched libstdc++ corrupts
the heap). On the Linux side gcc 16 is used for the static syntax check, but
the code must stay portable to any C++98 compiler and to Linux for testing.

## Layout

    include/        kdelibs-named headers (kdebug.h, kconfig.h, kparts/part.h, ...).
                    Header names and class APIs follow kdelibs 4.14 exactly so
                    Kate sources compile unmodified.
    include/KDE/    the CamelCase forwarders (KConfig -> ../kconfig.h,
                    KParts/Part -> ../../kparts/part.h), generated by
                    tools/gen-forwarders.sh. A separate directory, as kdelibs
                    installs them (include/KDE), because KIO/ and kio/ or
                    KParts/ and kparts/ side by side collide on case-insensitive
                    file systems (macOS default): the two directories merge and
                    every include resolves with a wrong-case path. Never add a
                    path that differs from an existing one only in case.
    src/core/       kernel: KGlobal, KComponentData, KStandardDirs, KAboutData,
                    KCmdLineArgs, KUrl, KLocale/i18n, kDebug, KUser, ...
    src/config/     vendored kconfig (KConfig, KConfigGroup, KSharedConfig, ini backend)
    src/gui/        KApplication, KGlobalSettings, icons, actions, widgets, dialogs,
                    KColorScheme, KAcceleratorManager (vendored), local-only
                    KUrlRequester and KHistoryComboBox, KFileDialog (static
                    helpers on the native dialogs; the dialog class is a KDialog
                    hosting a non-native QFileDialog, like KEncodingFileDialog)
    src/xmlgui/     vendored KXMLGUI + KMainWindow/KXmlGuiWindow/KToolBar/KMenuBar/KStatusBar
    src/parts/      KParts (Part, ReadOnlyPart, ReadWritePart, MainWindow, PartBase)
    src/io/         KTemporaryFile, KSaveFile, KDirWatch, KFilterDev, KProcess, KShell,
                    KMimeType, KCharsets, KEncodingProber, KService/KServiceTypeTrader
                    (.desktop files), KPluginLoader/KPluginFactory (static plugins),
                    KUrlCompletion (local paths only)
    src/sonnet/     Sonnet stubs (no spell checking yet; NSSpellChecker comes later)
    data/           icon theme subset and other resources compiled in via qrc
    tools/          syntax-check.sh, gen-forwarders.sh

Everything builds into one static library, `qt4compat`, linked into katepart,
kwrite and kate. The regex engine (`KatePcre`, pcre2) is not part of this
layer: it lives in part/utils and is Kate's own.

## Rules

* C++98 only: no `auto`, lambdas, `nullptr`, range-for, `override`, `enum class`,
  `>>` closing nested templates. Qt 4 idioms only: string based
  `SIGNAL()/SLOT()` connects, no `QStandardPaths`, `QRegularExpression`,
  `QSaveFile`, `QMimeDatabase`, `QStringLiteral`.
* Every class with `Q_OBJECT` lives in a header under `include/` (or a `_p.h`
  next to its source) and must be listed in `QT4COMPAT_MOC_HEADERS` in
  `CMakeLists.txt`; `.ui` files in `QT4COMPAT_UI_FILES`.
* Vendored kdelibs files keep their original license header. New files carry
  a one-line `qt4compat:` comment and are LGPL-2.0-or-later like Kate.
* Export macros (`KDECORE_EXPORT`, `KDEUI_EXPORT`, ...) are defined empty in
  `kdemacros.h`; keep using them so the code stays close to kdelibs.
* No KDE runtime assumptions: no D-Bus, no ksycoca, no kdeinit, no dynamic
  plugin loading. Services are the `services/*.desktop` files in the data
  directories (`KService::allServices()`, parsed with KConfig); a service
  that names a plugin library is listed by `KServiceTypeTrader` only when
  that plugin is linked in. Plugins keep their `K_PLUGIN_FACTORY` /
  `K_EXPORT_PLUGIN` sources: compiled with `KDE_STATIC_PLUGIN_NAME=<name>`
  (`kate_add_static_plugin()`) the export macro defines
  `kde_static_plugin_create_<name>()`, and `K_IMPORT_PLUGIN(<name>)` in the
  executable's own sources registers it with `KPluginLoader`, which hands out
  one factory instance per process (kexportplugin.h, kpluginloader.h).
  Anything else that would need a service returns an empty result.
* Resource files (XMLGUI `.rc`, syntax XML, scripts) are found via
  `KStandardDirs` (see kstandarddirs.h for the search order); on macOS they
  ship in the app bundle's `Resources`.
* macOS specifics go under `#ifdef Q_OS_MAC`; nothing may require Cocoa
  headers in the syntax-checked Linux build. Objective-C++ files (`.mm`) are
  fine when guarded in CMake with `if(APPLE)`.

## Syntax checking on Linux

    tools/syntax-check.sh [-I dir]... [-D def]... file.cpp [file.cpp ...]

runs moc/uic from the Qt 4.8.7 tree at `~/barracuda/qt4root` for every
`#include "foo.moc"` / `#include "ui_foo.h"` it finds, then `g++ -fsyntax-only`
against the Qt 4 headers. No cmake, no linking, no binaries. All of
`qt4compat/include`, the repository root, `includes/`, `ktexteditor/` and the
generated directory are on the include path by default.

## Kernel API contract (already written, do not change signatures)

* `KGlobal::config()`, `dirs()`, `locale()`, `charsets()`, `mainComponent()`.
* `KComponentData` registers itself as main component on first construction;
  `config()` calls `KSharedConfig::openConfig(*this, "<name>rc")`.
* `KStandardDirs` resource types: see kstandarddirs.h.
* `i18n()` family: UTF-8 in, `%1..%9` substitution, English plurals.
* `KUrl` is a `QUrl`; `KUrl("/abs/path")` becomes a `file:` URL.
* `KApplication` emits `openURLRequest(QUrl)` on `QFileOpenEvent`.
* `KGlobalSettings::fixedFont()` is Menlo/Monaco on macOS; `wheelMouseZooms()`
  is false (matches the MacPorts patch).
